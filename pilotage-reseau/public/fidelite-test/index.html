L’API de l’ERP, route par route

Pour tester sur le serveur ce que le cockpit sait faire avec l’API de l’ERP : la carte à points, les quatre cartes de bingo, la simulation d’un ticket, les clients et les bons dus. Lecture seule : rien n’est publié, aucun bon n’est émis — ces gestes se feront dans le cockpit. Page à part : elle ne touche ni au dashboard ni à l’écran Fidélité du cockpit, et a sa propre API (fidelite-test/api.php).

1. Vérifier l’API de l’ERP

Les cartes, la carte du programme, les magasins, les campagnes du bingo, les statistiques et les clients d’un magasin, la simulation de points. api.php?r=/fidelite/verification

2. Le programme

La carte à points et son barème, les quatre cartes de bingo de l’année, les bons et leurs campagnes. api.php?r=/fidelite

3. Simuler un ticket rien n’est écrit

api.php?r=/fidelite/simuler → POST /admin/loyalty/simulate

4. Les clients

Semaine par semaine, magasin par magasin : la première lecture d’une saison peut prendre une minute (ensuite, les semaines closes sont en cache un jour). api.php?r=/fidelite/clients

5. Les bons dus

Qui a gagné quel bon sur les semaines closes, et ce qui reste à émettre — en simulation. api.php?r=/fidelite/bingo/bons (toujours en simulation)
